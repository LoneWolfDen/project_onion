# Prompt: add the World of Continuum project handover to another app

Copy everything below the line into Claude Code in the other repository (Finance Engine or Pre-Sales/Delivery Accelerator). Fill in the two lines marked FILL IN first.

---

You are adding a cross-app project handover to this repository so that Continuum (https://github.com/LoneWolfDen/project_onion), the Finance Engine (https://github.com/LoneWolfDen/project_finance_engine) and the Pre-Sales Accelerator (https://github.com/LoneWolfDen/Project_Delivery_Accelerator_Engine) open each other on the same project, already filtered.

FILL IN: this app's id is `finance` (or `presales`).
FILL IN: the version or folder to change is `finance-engine-v3.5` (or the new browser-only app under `app/`).

The contract is in Continuum's repo at `docs/APP_HANDOVER_CONTRACT.md`, and a tested reference implementation is `modules/experience-pwa/static/js/core/appLink.js` with tests in `modules/experience-pwa/tests/appLink.test.mjs`. Read both first (clone the public repo or fetch the raw files) and follow the contract exactly. Summary:

1. A link is `<app address>#ctx=<base64url of JSON>`; JSON is `{ v: 1, from, ref, name, client, opp: [], pid: [], gdp, at }`. Identifiers only: never put content, amounts, rates, people, emails or notes in it. Max 2048 characters, max 10 items per list.
2. Receiving: read `ctx` from the fragment (and `?ctx=` as a fallback) on load and on `hashchange`, then remove it with `history.replaceState`. Validate strictly (drop unknown fields, ignore `v` other than 1, ignore contexts with no ref, opp, pid or gdp).
3. Resolve in order and stop at the first tier with any match: Continuum `ref` (if this app stored it before) → project ID (`pid`, compare numbers with leading zeros ignored) → opportunity number (`opp`, case-insensitive) → GDP ID. Never match on project name or client. One match: open that project already filtered. Several: select nothing and let the user pick. None: select nothing and say which IDs were asked for.
4. Show a banner: "Opened from Continuum: showing <project>, matched by <tier>", or the ambiguous or not-found message. A Dismiss button closes it.
5. Store the received `ref` against the matched project (for example a `continuumRef` field) so the next link matches exactly.
6. Sending: add footer links (or "Open in" buttons) to the other two apps that carry the active project's context with `from` set to this app's id. Addresses come from a small settings box saved in `localStorage` (key `world_app_urls`), with defaults; accept only `http:` and `https:`.

Where the IDs live in this app (check the code, do not assume):
- Finance Engine: the project ID is `Project ID` in timesheets, `projectID` in resource rules and the first part of `PO_Team_Identifier` (for example `111111_ProjectAlpha_AWS`). The dashboard filter for one project is the thing to drive. There is no opportunity number; send `pid` and `name`.
- Pre-Sales Accelerator: work starts before a project ID exists, so the opportunity number is the main key. If projects have no opportunity field yet, add one (optional, editable) and send `opp`.

Rules for this repository:
- Keep the existing architecture and conventions of this repo (read its README, CONTRIBUTING, `.claude/` and `docs/` first). Do not add a framework, bundler or new runtime dependency; the link code is plain JavaScript using `TextEncoder`, `btoa` and `atob`.
- No secrets, no network calls, no analytics. The fragment never reaches a server.
- Put the pure logic in its own module with unit tests (copy the test cases from Continuum's `appLink.test.mjs` and adapt them), and add a browser test (Playwright, if the repo has it) that opens the app with a link and checks the right project is shown, the banner text, and that the fragment is removed.
- Update the README with how to set the other apps' addresses.
- Work on a branch, open a pull request, and describe before/after in plain language.

Acceptance check you must run in a browser before finishing: open this app with a link generated by Continuum for a project that exists here (by project ID or opportunity); it opens filtered to that project with the banner; a link for an unknown ID selects nothing and says so; the footer link back to Continuum carries this project's IDs and opens the same project in Continuum.
