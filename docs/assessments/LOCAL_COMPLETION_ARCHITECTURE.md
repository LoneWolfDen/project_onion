# Continuum Local Completion Release: Target Architecture

Status: proposal only. No code has been changed.
Inputs: `docs/assessments/CURRENT_IMPLEMENTATION_ASSESSMENT.md` (evidence), owner constraints (below).
Backlog references in square brackets, for example [FND-01], point to `docs/backlog/LOCAL_COMPLETION_BACKLOG.md`.

## 0. Scope and constraints

**In scope.** A private, single-user, browser-based PWA on a restricted corporate laptop. Primary outcome: reliable project continuity and **grounded handover generation**.

**Out of scope.** Enterprise SaaS, multi-user hosting, public cloud, tenant-wide Graph access, an administration platform, and LDAP/Entra sign-in. The persona drop-down stays as it is, for testing.

**Hard constraints, with the design response to each:**

| Constraint | Design response |
|---|---|
| Browser PWA, no desktop install, no admin rights | Static files served from `127.0.0.1` by a tiny server (Python standard library, already in use). No Node, no pip packages for the core path. |
| No external transmission of client or project content | Remove default outbound AI calls. Allow-list network destinations to `127.0.0.1` only by default ([PRV-01], [PRV-02]). |
| Local-first | IndexedDB as primary store, `localStorage` for preferences only ([DAT-01]) |
| Single primary user | "Private / Team Shared" becomes **Draft / Approved**. Personas remain a test aid. |
| Human review before retention, publication or export | Three gates kept: Stage → Review → Approve. Handover has its own **Preview & Approve** step ([HND-04]). |
| Source provenance retained | A `Source` record for every import (file name, hash, sheet, row, captured-at, adapter version) ([DAT-03]) |
| Useful degraded mode | Every feature works with no AI and no vector service. Optional services only add to it. |
| No destructive cleanup without approval | Cleanup is listed only, in `REPOSITORY_CLEANUP_CANDIDATES.md` |
| Later Microsoft/Copilot/Azure use remains possible | Pluggable `SourceAdapter` and `AiProvider` interfaces. Handover exported as a portable Markdown/JSON package ([COP-01]). |

## 1. What "React no-build" should mean for this repository

**Definition (recommended):**
1. Application source is ES modules under `static/js/`, served exactly as written. What is in Git is what runs.
2. Components use **React 18 UMD + `htm`** tagged templates. No JSX, no TypeScript, no transpiler, no bundler, no `package.json` required to run.
3. Third-party code lives in `static/js/vendor/` as pinned, licence-recorded files, listed with version and SHA-256 in `static/js/vendor/VENDOR.md`. Vendor files are the **only** minified JavaScript.
4. CSS is hand-written, token-based and readable (`static/css/*.css`). No generated utility framework output is treated as source.
5. Generated artifacts (if any) have a generator script in the repo and a header naming it. Runtime data never lives under `static/` or `data/seed/`.
6. Running the app needs only `python3 -m http.server`-equivalent behaviour (the existing `service.py`), bound to `127.0.0.1`.

**Is it achievable?** Yes. The current UI already satisfies points 1, 2 and 3 (Observation, assessment §3.1). No framework migration is needed or recommended.

## 2. Smallest safe route to a human-editable, installable PWA

Order matters: first make data safe, then remove external calls, then make the app installable and maintainable.

| Step | Change | Why it is the smallest safe change |
|---|---|---|
| 1 | **Data safety:** full JSON export/import of the store, `navigator.storage.persist()`, write-failure surfacing, confirmation on reset [DAT-02], [DAT-04], [DAT-05], [HUI-05] | No UI restructuring. Prevents loss before anything else changes. |
| 2 | **Network boundary:** default AI provider = `none/local`; remote providers behind an explicit, off-by-default setting labelled "sends content off-device"; remove the hard-coded mock Q&A answers [PRV-01], [PRV-03] | Removes the only external transmission path and the only invented content |
| 3 | **Bind to 127.0.0.1** in `service.py` and other services; restrict CORS to `http://127.0.0.1:8002` [PRV-04] | One-line changes per service |
| 4 | **Manifest + icons + precaching SW** with a versioned cache, a precache list generated by a tiny Python script (`tools/build_precache.py`, run by hand, output committed with a header) and an "update available" prompt [PWA-01..04] | Makes the app installable in Chrome/Edge ("Install app"), which needs no admin rights. Gives a reliable offline shell. |
| 5 | **Readable CSS:** replace the frozen Tailwind block in stages. Add `tokens.css` + `components.css`, migrate one component at a time, then delete BLOCK 0 [HUI-02..03] | Visual regressions are contained per component and can be checked with screenshots |
| 6 | **Split large components:** `HarvesterPanel` → `DataParkInput`, `ReviewQueue`, `AiSettings`; `TimelineCard` → `CardHeader`, `ProvenanceList`, `NodeTimeline`; `HandoverModal` → `handover/model.js` (pure), `handover/render.js` (template), `HandoverDialog.js` [HUI-04] | Pure functions first, so they become unit-testable [TST-02] |
| 7 | **Storage move:** IndexedDB repository behind the existing `OnionDB` API, with one-time migration from `onion_db_state` and the localStorage copy kept as a backup [DAT-01] | Same API, so components do not change |

**Browser support.** The target is Chrome and Edge (Chromium 110+): ES modules, IndexedDB, service worker, install prompt and the File System Access API (optional). Safari 16.4+ supports ES modules, IndexedDB and service workers. Install there is "Add to Dock/Home Screen". It lacks the File System Access API (fall back to `<input type=file>` and download), and storage can be evicted after 7 days without use unless the app is installed, which makes export/backup essential [PWA-05].

**Accessibility and screen-sharing.** Base font 15–16px and minimum text 12px (current CSS uses 8–10px text in places: `text-[8px]`, `text-[9px]`). Contrast of at least 4.5:1 (pastel-on-pastel pills need checking). A visible focus ring. `prefers-reduced-motion` in the main stylesheet (currently absent). A "Presentation mode" toggle that raises font size and hides private drafts while screen-sharing [HUI-06], [HUI-07].

**Separation of source, generated output and runtime data:**
```
modules/experience-pwa/static/        source served as-is (+ vendor/)
modules/experience-pwa/static/precache.json   generated (header names tools/build_precache.py)
tools/                                developer scripts (python stdlib only)
data/seed/                            read-only fictional fixtures (never written at runtime)
<browser IndexedDB>                   runtime user data (never in Git)
~/Continuum/exports/                  user-chosen export location (outside the repo)
```

## 3. Handover outcome

### 3.1 Readiness today

| Required section | Current support | Gap |

**Verdict:** the plumbing (selection, grouping, HTML and print export, save to memory) is a sound base. Content grounding is **not** release-ready.

### 3.2 Required statement types (the "never invent" contract)

Every line in a handover is a **Statement** with exactly one `kind`, and the renderer must show the kind visibly:

| Kind | Definition | Required fields | Rendering rule | May AI produce it? |
|---|---|---|---|---|
| **Fact** | Directly stated in an approved source item | `sourceRefs[]` (≥1, approved), `quote` or `field` value, `asOf` date | Plain text plus citation chip(s) | No. Facts come from source fields or quotes. AI may only *select*, not rephrase without a quote. |
| **Inference** | Derived by a stated rule or model from facts | `basis[]` (fact IDs), `method` (`rule:<id>` or `model:<name>`), confidence | Italic, "Inferred:" prefix, method shown | Yes, labelled |
| **Recommendation** | Suggested action for the successor | `basis[]`, `author` (`user` or `model`) | "Suggested:" prefix, never mixed into Facts | Yes, labelled, and must be approved by the user |
| **Not found** | A required section had no qualifying evidence | `section`, `searchedSources[]`, `searchedAt` | "Not found in: GDP export 2026-09-28, RAID log v3…" | Generated by the system, never by AI |
| **Needs confirmation** | Evidence exists but is unreviewed, stale (> threshold), low-confidence or from a single unverified source | `reason` (`stale`, `unreviewed`, `single_source`, `low_confidence`), `sourceRefs[]` | Amber marker, listed again in an appendix | System |
| **Conflicting evidence** | Two or more approved sources disagree on the same field or subject | `claims[]` each with `sourceRefs`, `asOf` | Both values shown side by side with sources; no winner chosen unless the user resolves it | System detects, user resolves |

Rules:
- An empty section renders **Not found**. It never renders filler text.
- Numbers, dates, names and amounts appear only as Facts (with a source) or inside a labelled Inference.
- `aiEngine` = `mock` content may never appear as a Fact. The mock only truncates (`AiClient.mockResult`), so its output is shown as an "extract".
- Stale threshold: configurable per source (default: GDP 14 days, RAID 30 days, Connected 30 days).
- Export is blocked until the user opens Preview and confirms. The confirmation is logged with a timestamp and the package hash [HND-04].

### 3.3 Is a Decision entity necessary? (assessment only; do not add yet)

**Yes. It is the smallest addition that makes "key decisions and rationale" groundable.** Evidence: today "Decisions" is a keyword match (`TimelineCard.js:19` `hay.indexOf('decision')`), there is no rationale or decision-maker field, and V5's Hub promises "decisions, their sources and who approved them" with no entity behind it.

Proposed minimal shape (for the future backlog item [HND-07]):
```
Decision { id, projectRef, title, decidedOn, decidedBy (free text, not a directory lookup),
           rationale, alternativesConsidered?, status: proposed|confirmed|superseded,
           supersedes?, evidence: [sourceRef], createdFrom: cardId?, reviewedAt }
```
A Decision is created **only** by explicit user action ("Record as decision" on a card or RAID row), never by AI classification alone. Before it exists, the handover renders "Decisions: Not found as recorded decisions; N cards mention 'decision' (Needs confirmation)".

### 3.4 Handover pipeline (target)
```
approved Items + Sources + Project + (Decisions) ──► handover/model.js (pure, deterministic)
   ──► Statements[] with kinds ──► Preview (user edits / confirms / marks) ──► Package
Package = handover.md + handover.html + handover.json (statements + sources + hashes) + sources.csv
```
- The deterministic model is mandatory. AI wording is optional and is a separate, labelled "Draft narrative" that cites statement IDs.
- The package is the hand-off point to Copilot (see `COPILOT_INTEGRATION_OPTIONS.md`, pattern A).

## 4. Data model (target, minimal)

| Entity | Purpose | Notes |
|---|---|---|
| `Project` | Anchor (existing `projects[]`) | Keep `Project_ReferenceID` |
| `Source` | One imported file, paste or bookmarklet capture | `id, kind, fileName, sha256, importedAt, adapter@version, sheet?, rowCount, asOf, originHint (URL text, not fetched)` |
| `Item` (current timeline card) | A unit of knowledge | Add `sourceRefs[{sourceId,row?,field?}]`, `reviewState: staged|approved|rejected`, `asOf` |
| `Node` (existing RAW/AI) | Card history | Keep |
| `Decision` | See §3.3 | Later |
| `Handover` | Generated package metadata | `id, projectRefs, generatedAt, statementsHash, approvedAt` |
| `LogEntry` | Diagnostics | Separate store, bounded |

Store: IndexedDB database `continuum` v1 with object stores of the same names. Migration reads `onion_db_state` and the legacy keys once, writes them, and keeps the original key as `onion_db_state.backup-<date>` [DAT-01].

## 5. Degraded mode matrix

| Dependency missing | Behaviour |
|---|---|
| AI provider (default) | Extracts and keyword tags only, labelled "No AI". Handover fully works (deterministic). |
| Vector service (:8006) | Exact-hash and keyword duplicate detection only. A banner shows "Similarity search off". |
| Service worker unavailable | App works online from the local server. A banner explains the offline limits. |
| IndexedDB blocked (private window) | Read-only demo mode with a clear banner. Writes refused, not silently lost. |
| SheetJS fails on a file | The import fails with a message. No partial silent import. A CSV path is offered. |

## 6. Diagnostics design

| Requirement | Design |
|---|---|
| Timestamped logs | `core/log.js` with `log.info/warn/error(event, data)`: ISO time, level, module, event code, safe data |
| Unhandled errors | `window.addEventListener('error')` and `'unhandledrejection'` → `log.error('js.unhandled', {message, file, line, stackHash})` |
| Failed network requests | A `safeFetch` wrapper records method, **origin + path only**, status, duration and error class. **Never** headers or bodies. |
| SW events | SW `postMessage` → page logs `sw.install/activate/update/fetch-fail` |
| Storage failures | The repository logs `storage.write-failed {store, bytes, errorName}`, and the UI shows a blocking banner |
| Vector failures | `vector.unreachable`, `vector.queue-length` |
| Startup health | A `Diagnostics` page: storage persisted?, quota used/available, IndexedDB OK, SW state and version, vendor versions, optional services ping (127.0.0.1 only), app version (git commit stamped in `version.json` by hand) |
| Browser info | `navigator.userAgentData` brands/platform or a parsed UA. No fingerprinting extras. |
| Redaction | Allow-list logging (only declared fields). Strings run through `piiScreen` plus token patterns (`sk-…`, `Bearer …`, `eyJ…` JWT, `password=`). Content fields are never logged; only IDs and lengths are. |
| Bounded retention | IndexedDB `logs` store, ring buffer of 5,000 entries or 7 days, whichever comes first |
| Rotation | Daily segments; the oldest are dropped first |
| User export | "Export diagnostics" → user previews, then downloads `continuum-diagnostics-<date>.json`. Never uploaded. |
| DevTools guidance | Doc: Chrome/Edge F12 → Console (filter `[continuum]`), Application → Storage / IndexedDB / Service Workers ("Update on reload", "Unregister"), Network ("Preserve log", "Disable cache"), with the reminder not to share HAR files (they contain content) |
| Terminal logging | `python3 service.py 2>&1 | tee -a ~/Continuum/logs/server-$(date +%F).log`. The server logs method, path and status only (`log_message` override strips the query string). |
